# Third Party Preparation Implementation Plan

> **For agentic workers:** Use executing-plans for root implementation and dispatching-parallel-agents for independent scoped source discovery. User requests continuous preparation, followed by consolidated testing.

**Goal:** 为既有 I01—I17 外联准备完整的本地适配、配置/部署入口、资料清单与后续测试包，准确列出外部资料和代码阻塞。

**Architecture:** 继续使用现有 Spring 配置、SDK、数据库配置实体和前端入口。新准备配置采用独立 opt-in overlay；默认不激活外部任务，不改变当前公开服务。

**Tech Stack:** Java 8 / Spring Boot / existing locked SDK dependencies / Docker Compose / Python standard library.

**Spec:** `docs/superpowers/specs/2026-11-06-third-party-preparation-design.md`

## Global Constraints

- 用户明确先全部准备再测试；准备阶段不执行真实第三方请求或硬件操作。测试脚本先准备，最后统一离线核查；外部资料齐全后才真实联调。
- 不改原用户库、不重启当前 app90/web93、不覆盖旧验收或原备份。不开启旧外部 Runner/定时扫描。
- 任何私有值只保存在 `integrations/private/` 或 `integrations/runtime/`，报告仅保留配置名与是否存在。
- 使用当前工作目录保留所有未跟踪的既有源码，避免新建仅有初始化 README 的工作树导致遗漏。不提交/推送，不改远端。
- 产品源码编辑前保存私有原文副本及 SHA，所有模块来源登记由 root 统一处理。

## Review Focus

- 有变量名但未通过容器环境传递；准备脚本必须检查源码读取入口与部署配置对应关系。
- 假凭据/占位地址被误认真实准备完成；状态清单必须保持待资料状态。
- 默认配置开启外部副作用；overlay 与已运行服务隔离，开关默认关闭。
- 微信旧令牌和现鉴权不兼容、回调需验签；单独记录并按真实协议解决，不广泛开放匿名权限。
- 不同套料/OSS入口保留独立硬编码；审计实际调用者，不仅修改公共工具类。
